# 知识图谱配置

> 这里的“知识图谱”指 **LLM 抽取的实体-关系图**（Neo4j）。
> 它与 Wiki 知识库里的“页面链接图谱”是两回事：前者从文本抽取实体和关系，后者是 Wiki 页面之间的引用关系。

## 启用条件

图谱能力需要 Neo4j，且由环境变量门控：

| 变量 | 说明 |
|---|---|
| `NEO4J_ENABLE` | 必须为 `true`（忽略大小写）才创建驱动；其他值 = 不启用 |
| `NEO4J_URI` | 如 `bolt://localhost:7687` |
| `NEO4J_USERNAME` | 用户名 |
| `NEO4J_PASSWORD` | 密码 |

注意：`NEO4J_ENABLE=true` 但连不上时，**启动会失败**，不会静默降级。配置前先确认 Neo4j 可达。

未启用时，知识库设置里的图谱页会显示“未启用”提示与启用指引；系统信息页的 `graphDatabaseEngine` 显示 `Not Enabled`。

## 知识库配置

入口：知识库 → 设置 → **知识图谱配置**。

| 配置 | 作用 |
|---|---|
| 启用实体关系提取 | 打开后，入库/重处理时自动从文本抽取实体和关系 |
| 关系类型 | 期望抽取的关系标签，逗号分隔，如“工作于、同事、朋友” |
| 额外提取要求 | 领域范围、实体筛选、属性要求；系统仍负责结构化输出协议 |
| 示例文本 | 用于试跑抽取，确认提示词与关系类型是否合适 |
| 实体列表 / 关系列表 | 试跑结果的管理与校正 |
| 开始提取 | 对示例文本执行一次抽取，验证配置 |

抽取依赖对话模型；页面提示“请先完成模型配置”时，先到模型管理里配好 KnowledgeQA 模型。

## 抽取与检索

1. **抽取**：文档分块后，按知识库配置的关系类型与额外要求调用对话模型，产出实体/关系。
2. **落库**：实体与关系写入 Neo4j；同一知识库的图谱按租户/知识库隔离。
3. **检索**：问答时图谱召回与向量/关键词召回一起参与融合（具体权重与开关按知识库检索配置）。
4. **重处理**：修改关系类型或额外要求后，需要重新处理文档才会按新配置重建图谱。

## 常见问题

| 现象 | 检查 |
|---|---|
| 图谱页显示未启用 | `NEO4J_ENABLE` 是否为 `true`；改完是否重启 |
| 启动直接失败 | Neo4j 地址/账号/网络是否可达；门控打开后连不上是启动失败 |
| 抽取结果为空 | 关系类型是否过于具体；示例文本是否包含可抽取实体；对话模型是否可用 |
| 提示“请先完成模型配置” | 先在模型管理里配置默认 KnowledgeQA 模型 |
| 改了配置没变化 | 已入库文档需要重新处理；只改设置不会回填旧图谱 |
| 与 Wiki 链接图混淆 | 本页是实体-关系图；Wiki 页面链接图在 Wiki 知识库内查看 |
