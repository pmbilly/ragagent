# IM 渠道接入

> 把 Agent 接到企业微信、微信、飞书、钉钉、Slack 等 IM，让用户在聊天窗口里直接提问。
> 入口：Agent 编辑器 → **集成** → **IM**。

## 支持的渠道

| 渠道 | 标识 | 接入方式 |
|---|---|---|
| 企业微信 | `wecom` | webhook / 长连接 |
| 微信（公众号等） | `wechat` | webhook |
| 飞书 | `feishu` | webhook / 长连接 |
| 钉钉 | `dingtalk` | webhook / 长连接 |
| Slack | `slack` | webhook |
| 通用 IM | `im` | 由自定义适配器实现 |

具体可用方式取决于渠道配置里的“接入模式”；新建渠道时页面会按渠道给出可选项。

## 配置步骤

1. **在 Agent 编辑器创建渠道**
   - 路径：Agent → 集成 → IM → 新建渠道。
   - 选择渠道类型、绑定 Agent、填写平台凭据（App ID / Secret / Token / 回调签名等，按渠道而异）。
   - 记录页面生成的**回调地址**。

2. **在平台侧填回调地址**
   - 形如：`https://<你的域名>/api/v1/im/callback/{channelId}`
   - 平台会分别以 GET（校验）与 POST（消息）请求该地址。

3. **开启渠道**
   - 渠道列表里切换启用状态（`/api/v1/im-channels/{id}/toggle`）。
   - 未启用的渠道不会接收/回复消息。

4. **验证**
   - 在对应 IM 里 @ 机器人或私聊发送一条文本。
   - 观察后端日志与渠道状态；首次接入常见问题是回调地址不可达或凭据错误。

## 消息能力

- 消息类型：文本、图片、文件。
- 会话类型：单聊（direct）、群聊（group）。
- 群聊里通常需要 @ 机器人才触发；具体以渠道适配器为准。
- 回复走各平台自己的发送接口；钉钉群聊可能使用临时 `session_webhook`，飞书/企微按应用凭据发送。

## 回调与安全

- 回调路径固定为 `/api/v1/im/callback/{channelId}`，**不套统一 `{code,message,data}` 外壳**——平台要求什么 ACK 就返回什么，避免第三方重试。
- 回调请求按渠道凭据校验（签名/Token/Encrypt Key 等），不依赖租户 JWT。
- 出站请求（回复、拉取用户信息、下载媒体）过 SSRF 守卫；自建/内网回调地址需要加入白名单。
- 渠道凭据加密存储；页面上不应回显完整 secret。

## 常见问题

| 现象 | 优先检查 |
|---|---|
| 平台校验回调失败 | 回调 URL 是否公网可达；GET 校验返回值是否符合平台要求 |
| 发消息无回复 | 渠道是否启用；Agent 是否绑定；平台凭据是否过期 |
| 群聊不触发 | 是否需要 @ 机器人；群聊权限/应用可见范围 |
| 图片/文件收不到 | 平台媒体下载地址是否被 SSRF 拦；渠道是否允许该消息类型 |
| 重复回复 | 平台重试；检查回调 ACK 是否按平台要求返回 |
| 日志报 `origin not allowed` | 这是 Embed 渠道的错误，不是 IM；检查是否走错入口 |
